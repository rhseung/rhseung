포트폴리오를 Astro로 옮기면서 프로젝트 상세 페이지를 만들었다. 브라우저에서는 멀쩡했다.
빌드 결과물을 열어보기 전까지는.

<Figure caption="빌드된 HTML. 본문이 전부 하이드레이션 템플릿 안에 있다">

```html
<astro-island ssr client="idle" await-children>
  <template data-astro-template
    ><h2>왜 만들었나</h2>
    …</template
  >
</astro-island>
```

</Figure>

본문이 전부 `<template>` 안에 있었다. 서버가 그린 HTML에는 아무것도 없고, JavaScript가
돌아야만 내용이 나타난다. 크롤러가 보는 건 빈 문서다.

## 원인

템플릿에서 물려받은 `AppProviders`가 이렇게 생겼었다.

```tsx
const [ready, setReady] = useState(import.meta.env.PUBLIC_ENABLE_MSW !== 'true');
// …
if (!ready) return null;
```

MSW(Mock Service Worker)가 켜져 있으면 워커가 준비될 때까지 자식을 렌더하지 않는다.
API를 붙인 SPA에서는 맞는 판단이다 — 먼저 그려지면 워커가 뜨기 전에 진짜 요청이 나가버린다.

문제는 이 코드가 **빌드 타임 렌더에도 그대로 실행된다**는 것이다. 서버에는 서비스워커가
없으니 `ready`는 영원히 `false`고, 컴포넌트는 `null`을 반환한다. Astro는 아일랜드가
아무것도 안 그렸다고 판단하고, 슬롯으로 받은 본문만 하이드레이션용 템플릿에 실어 보낸다.

## 왜 늦게 발견했나

`.env`가 `.gitignore`에 있었다. 배포 빌드에는 `PUBLIC_ENABLE_MSW`가 아예 없어서
`ready`가 처음부터 `true`였다. **프로덕션만 우연히 멀쩡했고**, 로컬 빌드와 e2e는 계속
다른 렌더 경로를 타고 있었다.

| 환경         | `PUBLIC_ENABLE_MSW` | `ready` 초기값 | 본문이 HTML에 |
| ------------ | ------------------- | -------------- | ------------- |
| 로컬 `dev`   | `true`              | `false`        | 없음[^dev]    |
| 로컬 `build` | `true`              | `false`        | 없음          |
| CI · Vercel  | _(없음)_            | `true`         | 있음          |

[^dev]: 브라우저에서는 하이드레이션이 끝나면 보이니까 눈으로는 구분이 안 된다.

증상이 없는 게 아니라, 증상을 볼 수 있는 곳에서만 없었다.

> 서버에서 아무것도 렌더하지 않은 아일랜드는, 서버가 _실패한_ 아일랜드와 구분되지 않는다.
> Astro 입장에서는 둘 다 "이 아일랜드는 클라이언트가 그린다"일 뿐이다.

<Callout tone="warn" title="환경변수가 렌더 경로를 가르면">
  `.env`가 커밋되지 않는 한, 로컬과 배포는 다른 코드를 실행한다. 렌더 여부를 정하는 플래그는 특히
  위험하다 — 한쪽에서만 나는 버그가 되고, 하필 안 나는 쪽이 프로덕션일 수 있다.
</Callout>

## 고친 방법

게이트를 지웠다. 이 사이트의 콘텐츠는 전부 빌드 타임 content collection이라 런타임에
나가는 요청이 하나도 없다 — 막을 경합이 애초에 없었다.

```tsx
useEffect(() => {
  void ensureMocking();
}, []);
```

그리고 회귀 테스트를 남겼다. 이런 버그는 눈으로 안 보이니까 테스트가 대신 봐야 한다.

```ts
const context = await browser.newContext({ javaScriptEnabled: false });
```

JavaScript를 끈 브라우저로 페이지를 열어 본문이 읽히는지 확인한다. 아일랜드가 다시
SSR을 건너뛰면 여기서 걸린다.

<Figure caption="JavaScript를 끈 브라우저. 고친 뒤에는 본문이 그대로 읽힌다 — 테마 스크립트도 안 돌아 라이트로 뜬다">

![JavaScript를 끈 브라우저에서 프로젝트 상세 페이지가 정상으로 렌더된 화면](./assets/no-js.png)

</Figure>

<Steps>
  <Step index={1} title="빌드 결과물을 연다">
    `dist/**/index.html` 을 직접 본다. 브라우저에서 멀쩡한 것은 아무 증거도 아니다.
  </Step>
  <Step index={2} title="astro-island[ssr] 을 센다">
    이 속성이 남아 있으면 그 아일랜드는 서버에서 아무것도 안 그렸다는 뜻이다.
  </Step>
  <Step index={3} title="JS 를 끄고 다시 연다">
    본문이 읽히면 통과. 이 셋을 e2e 로 굳혀두면 다시는 눈으로 안 봐도 된다.
  </Step>
</Steps>

## 남는 것

아일랜드가 $n$ 개인 페이지에서 서버가 그리는 본문의 비율을 $r$ 이라 하자. 게이트가 하나만
있어도 그 아래 전부가 빠지니, $r$ 은 연속적으로 나빠지지 않고 한 번에 떨어진다.

$$
r = \frac{1}{n} \sum_{i=1}^{n} [\, \text{island}_i \text{ rendered on server} \,]
$$

수정 전에는 상세 페이지에서 $r = 0$ 이었다.

  <Stat value="14" label="같은 버그를 안고 있던 페이지" />
  <Stat value="1" label="원인이 된 조건문" />
</Stats>

정적 사이트에서 "렌더를 막는" 코드는 전부 의심 대상이다.

- **로딩 게이트** — `if (!ready) return null`
- **인증 게이트** — 세션이 없으면 자식을 안 그리는 래퍼
- **피처 플래그 게이트** — 플래그를 원격에서 받아오는 동안 비워두는 코드
  - 원격에서 받아오는 순간 빌드 타임에는 영원히 `undefined`다
  - 기본값을 코드에 박아두면 이 부류는 사라진다

클라이언트에서는 한 프레임이지만 빌드 타임에는 영원이다.
