## 개요

2026년 버전 개발자 Macbook 종합 세팅, 대부분의 설정은 [dotfiles](https://github.com/rhseung/dotfiles) 저장소에 들어있으나 세부적인 것을 정리하기 위해 작성했다.

해당 저장소 README에 나와있듯이 몇 가지 선행 조건을 만족한 뒤 다음 스크립트로 대부분의 설정을 적용할 수 있다.

```zsh
brew install chezmoi

chezmoi init --apply https://github.com/rhseung/dotfiles.git
brew bundle --file ~/.local/share/chezmoi/Brewfile
```

앱과 CLI 도구 목록은 [Brewfile](https://github.com/rhseung/dotfiles/blob/main/Brewfile), 셸 설정은 [dot_zshrc](https://github.com/rhseung/dotfiles/blob/main/dot_zshrc)에 있다. 아래에서도 각 항목마다 해당 파일을 걸어뒀다.

자동화 되지 않은 것들은 다음과 같다.

- **[Mise](#mise), [uv](#uv), [Bun](#bun)은 각자 설치 스크립트로 깐다.** Homebrew로 깔면 `mise self-update`, `uv self update`, `bun upgrade`가 막혀서 Brewfile에 안 넣었다.
- **직접 받는 것들**: [Raycast](#raycast-v2), 교내 배포처의 오피스류, 유료 폰트 [MonoLisa](#monolisa), [Setapp](#setapp) 안에서 받는 앱들, 한국 서버 [League of Legends](#게임).
- **GUI로만 되는 macOS 설정**

## 시스템 설정

### 컴퓨터 이름

터미널 프롬프트에서 `@` 뒤에 붙는 그 이름이다. 시스템 설정 > 일반 > 정보에서 바꿔도 프롬프트는 그대로인 경우가 많은데, macOS가 이름을 셋으로 나눠 들고 있어서다.

| 이름            | 어디에 쓰이나                                      | GUI 로 바꾸는 곳                      |
| --------------- | -------------------------------------------------- | ------------------------------------- |
| `ComputerName`  | Finder 공유 목록, 시스템 설정에 보이는 이름        | 일반 > 정보 > 이름                    |
| `LocalHostName` | Bonjour 이름. 같은 네트워크에서 `.local`로 부를 때 | 일반 > 공유 > 로컬 호스트 이름 > 편집 |
| `HostName`      | 셸 프롬프트의 `@` 뒤                               | 없음                                  |

앞의 둘은 GUI 로 된다 - 각자 다른 화면에 떨어져 있어서 `정보`만 보면 `LocalHostName`은 안 바뀐 것처럼 보일 뿐이다.

1. **시스템 설정 > 일반 > 정보 > 이름**에서 `ComputerName`을 바꾼다.
2. **시스템 설정 > 일반 > 공유**로 들어가서, 하단 `로컬 호스트 이름` 옆의 **편집**을 눌러 `LocalHostName`을 바꾼다. 공백도 한글도 못 받으니 영문 소문자와 하이픈으로 짓는다.

`HostName`은 GUI 자체가 없다. 비워두면 프롬프트에 `LocalHostName`이 `.local`을 달고 나오는데, 그게 싫으면 그때만 터미널을 쓴다.

```zsh
sudo scutil --set HostName "rhseung-macbook"
```

### 한/영 키 변경

오른쪽 <Shortcut keys={['cmd']} /> (HID 0x7000000E7)를 <Shortcut keys={['F18']} /> (0x70000006D)로 보낸다. `hidutil`로 바로 리매핑하면 재부팅에 풀려서, [LaunchAgent](https://github.com/rhseung/dotfiles/blob/main/private_Library/LaunchAgents/local.hidutil.rcmd-to-f18.plist)에 `RunAtLoad`로 걸어 로그인할 때마다 다시 잡는다.

매핑부터 켜야 한다. 노트북 키보드엔 <Shortcut keys={['F18']} />이 물리 키로 없어서, 오른쪽 <Shortcut keys={['cmd']} />가 그 신호를 실제로 보내고 있어야 다음 단계의 단축키 녹화기가 F18을 잡는다.

```zsh
# check
hidutil property --get UserKeyMapping
```

**시스템 설정 > 키보드 > 키보드 단축키 > 입력 소스**에서 "이전 입력 소스 선택"을 켜고 단축키를 Right <Shortcut keys={['cmd']} />로 바꾼다.

## 개발 환경 준비

### macOS 업데이트와 칩 확인

먼저 macOS를 최신 상태로 업데이트한다.

```zsh
softwareupdate --list
```

또한 현재 macOS 버전은 다음과 같이 확인할 수 있다.

```zsh
sw_vers
```

Mac의 칩 종류는 아래 명령어로 확인한다.

```zsh
uname -m
```

결과가 `arm64` 라면 Apple Silicon 계열이며, `x86_64` 이면 Intel Mac이다.

### 개발 폴더

저장소는 홈 아래 `~/Developer`에 clone해서 쓴다. macOS가 몇몇 홈 폴더 이름을 예약어로 다뤄서 전용 아이콘을 자동으로 붙여주는데, `Developer`도 그중 하나다.

```zsh
mkdir -p ~/Developer
```

### [Xcode Command Line Tools](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools)

clang 컴파일러와 SDK 헤더, 그리고 Homebrew 설치에 필요하여 먼저 Xcode Command Line Tools를 설치하는 것이 좋다.

```zsh
xcode-select --install

# check
xcode-select -p
clang --version
```

### [Homebrew](https://brew.sh/)

가장 유명한 macOS 패키지 매니저이다.

```zsh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

이후 터미널에 Next steps 항목이 나오는데, 그걸 따라 `~/.zshrc` 같은 각 터미널 설정 파일에 넣어주면 된다.

### [mas](https://github.com/mas-cli/mas)

Mac App Store CLI. App Store 앱을 GUI 대신 CLI로 사용할 수 있어, [Homebrew](#homebrew)에 없는 앱들은 `mas`로 설치해주면 된다.

```zsh
mas search klack
mas install 6446206067
```

## 필수 앱

1Password를 먼저 설치한다. 뒤에 나오는 대부분이 로그인을 요구하기 때문이다.

### [1Password](https://1password.com/)

비밀번호와 패스키, 2단계 인증 코드를 한 금고에 모아 기기 사이로 동기화해주는 관리 앱이다. SSH 키와 API 토큰까지 같은 금고에 넣어 Touch ID로 꺼내 쓸 수 있다.

[1Password CLI](https://developer.1password.com/docs/cli/)까지 같이 깔면 [셸 플러그인](https://developer.1password.com/docs/cli/shell-plugins/)이 붙는다. `gh`나 `aws`처럼 토큰이 필요한 CLI를 Touch ID로 대신 인증해주고, [git 커밋 서명](https://developer.1password.com/docs/ssh/git-commit-signing/)은 SSH 에이전트가 금고의 키로 처리한다.

#### 커밋 서명

금고에서 **New Item > SSH Key** 로 키를 만든다. `ssh-keygen` 으로 만들어 넣어도 되지만, 금고에서 만들면 개인 키가 금고 밖으로 유출될 일이 없기에 이 방법을 추천한다.

앱 설정의 **Developer** 탭에 SSH 에이전트를 켜고 git 커밋 서명까지 대신 해주는 버튼이 있다. 눌러 두면 `~/.ssh/config`와 `~/.gitconfig`를 알아서 써 주니 할 일은 GitHub에 공개키를 **Signing Key** 타입으로 올리면 된다.

### [AdGuard](https://adguard.com/ko/welcome.html)

로컬 프록시로 트래픽을 거쳐 보내며 브라우저 밖 앱 안의 광고까지 걸러주는 차단기이다.

AdGuard는 다양한 옵션을 지원하는데, 한국의 웹사이트들에서도 잘 작동하게 하려면 커스텀 필터, 유저스크립트를 추가해야한다.

- [filterslists-KO](https://github.com/FilteringDev/filterslists-KO): AdGuard와 애드블록 커뮤니티에서 관리하는 한국어 광고 차단 필터 리스트
- [tinyShield](https://github.com/FilteringDev/tinyShield): Ad-Shield 방식의 Adblock Blocker를 막는 유저스크립트
- [NamuLink](https://github.com/FilteringDev/NamuLink): 나무위키의 처리하기 복잡한 파워링크를 차단하는 유저스크립트
- [crackle](https://github.com/FilteringDev/crackle): 네이버 치지직 웹 사이트의 광고 제거 및 안티 애드블록 우회를 위한 유저스크립트

## 유틸리티 앱

- [Alcove](https://tryalcove.com/): 아이폰의 다이나믹 아일랜드를 맥 노치로 옮겨온 앱. 재생 중인 음악, 에어드랍, 충전, 캘린더를 노치에 띄운다
- [Klack](https://tryklack.com/): 키를 누를 때 기계식 키보드 소리를 낸다
- [Vorssaint](https://vorssaint.com/): 메뉴 바에서 쓰는 무료 오픈소스 시스템 툴킷. 화면을 닫아도 절전에 안 들어가게 하는 Keep-awake, CPU/GPU 온도와 배터리, 메모리 모니터링, 다크 모드 토글까지 필요한 모듈만 골라 켠다

## Fonts

### [Pretendard](https://cactus.tistory.com/306)

Pretendard는 San Francisco와 Apple SD 산돌고딕 Neo가 없는 다른 환경에서 이를 대체할 수 있는 글꼴, system-ui를 대체하는 글꼴이다. 본문용 한글 산세리프로써 많은 곳에서 사용되고 있다.

[Pretendard GOV](https://github.com/orioncactus/pretendard/tree/main/packages/pretendard-gov)는 개중에서도, 범정부 디자인시스템(KRDS)의 표준 글꼴에 사용되는 것을 목적으로 다듬어진 글꼴이다. 정부의 웹사이트와 앱, 각종 증명서에 쓰이는 만큼 한 글자도 잘못 읽히면 안 되므로, 헷갈리는 글자들을 서로 다르게 그렸다. 대문자 I, 소문자 l, 숫자 1과 구분되고, O와 0, w와 vv도 모양이 갈린다. 이 블로그에서도 쓰고 있다.

### [IBM Plex Sans KR](https://fonts.google.com/specimen/IBM+Plex+Sans+KR)

IBM이 만든 오픈소스 산세리프 [Plex Sans](https://fonts.google.com/specimen/IBM+Plex+Sans)의 한글 지원 버전이다. Pretendard보다 개성이 있어서, 같은 글이라도 분위기를 바꾸고 싶을 때 문서용으로 쓴다.

### [Monaspace](https://monaspace.githubnext.com/)

GitHub가 만든 코딩용 폰트로, 네오그로테스크 산세리프 Neon, 휴머니스트 산세리프 Argon, 슬래브 세리프 Xenon, 손글씨 Radon, 기계식 산세리프 Krypton의 다섯 variant가 있다.

다섯 배리언트가 폭이 같아서, 코드 안에서 서체를 섞어도 격자가 안 어긋난다. 여기에 좁은 글자 옆의 여백을 넓은 글자로 빌려줘서, 고정폭 특유의 듬성듬성한 느낌 없이 균일하게 보이게 하는 Texture Healing이 구현되어있다.

### [MonoLisa](https://www.monolisa.dev/)

MonoLisa는 유료 코딩 폰트로, 위의 Monaspace 같은 네오그로테스크 계열과 달리 글자마다 개성이 있는데, 그 덕에 오래 봐도 눈이 덜 피로하면서 가독성도 훌륭하다. Ligature와 OpenType feature 지원도 폭넓어서 취향대로 켜고 끌 수 있다.

#### Nerd Font 글리프

MonoLisa는 Nerd Font 글리프를 담고 있지 않다. [MonoLisa FAQ](https://www.monolisa.dev/faq#how-to-enable-nerd-fonts-with-monolisa)는 폰트를 직접 패치하기보다 폴백 폰트를 두는 쪽을 권한다. 패치본은 MonoLisa를 새로 받을 때마다 다시 구워야 한다.

아이콘 글리프만 담은 Symbols Nerd Font가 그 폴백이다.

[VS Code](#visual-studio-code)는 `fontFamily`에 콤마로 잇는다.

```json
"terminal.integrated.fontFamily": "'MonoLisaCode', 'Symbols Nerd Font Mono', 'Pretendard GOV Variable', Menlo, Monaco, 'Courier New', monospace"
```

[Ghostty](#ghostty)는 `font-family`를 줄마다 하나씩 쌓아 폴백을 만든다.

```
font-family = "MonoLisaCode"
font-family = "Symbols Nerd Font Mono"
font-family = "Pretendard GOV Variable"
```

폴백으로 안 되는 환경에서는 [nerd-fonts의 font-patcher](https://github.com/ryanoasis/nerd-fonts#font-patcher)로 폰트에 글리프를 직접 굽는다. variable 폰트는 받지 않으니 `MonoLisa-Regular.ttf` 같은 static instance를 넘긴다.

```zsh
git clone --depth 1 https://github.com/ryanoasis/nerd-fonts.git
cd nerd-fonts

./font-patcher ~/Library/Fonts/MonoLisa-Regular.ttf --complete
```

패치된 폰트가 `~/Library/Fonts`에 새로 생기면 그걸 터미널·에디터 설정의 `font-family`에 지정한다.

### [0xProto](https://github.com/0xType/0xProto)

코드 가독성에 초점을 맞춘 오픈소스 코딩 폰트다. `0`/`O`, `1`/`l`/`I`처럼 헷갈리는 글자를 확실히 구분하고, [Monaspace](#monaspace)와 같은 Texture Healing으로 좁은 글자 옆 넓은 글자를 미세하게 줄여 균일하게 보이게 한다. 또한 Ligature를 지원하되 형태를 완전히 변형하여 헷갈리게 만드는 방식을 지양하여 설계한 점이 개성있다.

## 셸 환경

### [chezmoi](https://www.chezmoi.io/)

```zsh
chezmoi init
chezmoi add ~/.zshrc
```

- `ctrl+t`: 파일 검색해서 커맨드에 끼워넣기

`cd`를 대신한다. 한 번 가본 디렉터리를 기억해뒀다가, 이름 일부만 쳐도 그중 제일 자주 간 곳으로 바로 이동시켜주는 편리한 도구이다.


### [Starship](https://starship.rs/)

어떤 셸에서든 쓰는 프롬프트다. 가볍고 빠르면서 원하는 대로 커스터마이징할 수 있다. 지금 디렉터리가 git 저장소면 브랜치와 변경 상태를, 언어별 프로젝트면 그 언어 버전을 바로 띄운다.

가장 많이 쓰이는 [Powerlevel10k](https://github.com/romkatv/powerlevel10k)도 있지만 무겁기도 하고 Starship의 기본값이 워낙 예뻐서 쓴다. Starship은 TOML 설정 파일을 쓰기에 [chezmoi](#chezmoi)로도 유용하다. 설정은 [starship.toml](https://github.com/rhseung/dotfiles/blob/main/dot_config/starship.toml)이다.

### Zsh

#### 플러그인

`fzf-tab`은 zsh의 기본 선택 메뉴를 [fzf](#fzf)로 갈아끼우는 것이라 fzf가 깔려 있어야 한다. 로드 순서가 까다롭다.

- `zsh-completions`는 `FPATH`에 얹히므로 `compinit` 앞
- `fzf-tab`은 `compinit` 뒤이면서, 위젯을 감싸는 `zsh-autosuggestions`·`zsh-syntax-highlighting`보다 앞
- `zsh-syntax-highlighting`은 `zsh-history-substring-search`보다 먼저

경로에 쓰는 `$HOMEBREW_PREFIX`는 [Homebrew](#homebrew) 설정 때 넣은 `brew shellenv`가 채워주므로 Intel/ARM을 안 가린다. `zsh-history-substring-search`는 위/아래 화살표에 `bindkey`를 따로 걸어야 동작한다.

- [zsh-completions](https://github.com/zsh-users/zsh-completions): 기본 zsh에 없는 커맨드용 자동완성 정의 모음
- [zsh-autosuggestions](https://github.com/zsh-users/zsh-autosuggestions): 히스토리 기반으로 입력 중인 줄 뒤에 회색 제안을 띄운다.
- [zsh-syntax-highlighting](https://github.com/zsh-users/zsh-syntax-highlighting): 입력하는 즉시 명령어, 경로에 문법 강조를 입힌다.
- [zsh-history-substring-search](https://github.com/zsh-users/zsh-history-substring-search): 위/아래 화살표로 지금까지 입력한 부분 문자열을 포함하는 히스토리만 훑는다.
- [zsh-you-should-use](https://github.com/MichaelAquilina/zsh-you-should-use): 방금 친 명령이 등록된 alias 로 대체 가능하면 알려준다
- [fzf-tab](https://github.com/Aloxaf/fzf-tab): tab 자동완성 목록을 fzf 로 갈아엎어 뒤진다

## 버전 관리

### [Git](https://git-scm.com/)

버전 관리 시스템이다. [Xcode Command Line Tools](#xcode-command-line-tools)에서 같이 설치 되지만 최신 버전으로 쓰려면 Homebrew로 설치하는 것이 좋다.

`/opt/homebrew/bin`이 `/usr/bin`보다 PATH 앞에 있으면 정상적으로 잡을 수 있다.

```zsh
# PATH order
which -a git

# check
git --version
```

#### Git 설정

[`.gitconfig`](https://github.com/rhseung/dotfiles/blob/main/private_dot_gitconfig)에 모았다. 이름과 이메일은 [커밋 서명](#커밋-서명)까지 했다면 서명 키의 이메일과 맞춰야 한다. 서명은 1Password의 `op-ssh-sign`이 맡아서 `gpg.format`이 `ssh`다.

diff 페이저는 [delta](#delta)로 두고, 머지 충돌은 `zdiff3`로 바꾼다. `zdiff3`은 conflict 전 원본 내용까지 같이 보여줘서 가늠하기가 더 쉽다. git에 내장된 옵션이라 따로 설치할 건 없다.

macOS가 폴더마다 생성하는 `.DS_Store`는 글로벌 `.gitignore`에 적는 것이 낫다. [`~/.config/git/ignore`](https://github.com/rhseung/dotfiles/blob/main/dot_config/git/ignore)가 기본 전역 gitignore이다.

### [GitHub CLI](https://cli.github.com/)

CLI로 깃허브의 PR, 이슈, 릴리스 등의 기능들을 사용할 수 있게 하는 툴이다. 브라우저를 안 열어도 되고, 사람이 사용하기 쉽고 AI Agent가 쓰기도 쉽다.

`gh auth login`으로 한 번 로그인해두면 git push/pull에도 인증을 쓸 수 있다.

### [serie](https://github.com/lusingander/serie)

git 커밋 그래프를 터미널에서 보여주는 TUI다. `git log --graph`보다 훨씬 보기 편하다.

### [delta](https://dandavison.github.io/delta/)

`git diff`를 더 개선해서 그려주는 페이저다. 나란히 보여주고 문법 강조까지 되어 훨씬 읽기 편해진다.

## 언어 환경

### [Mise](https://mise.jdx.dev/)

Node, Python, Rust 같은 런타임 버전을 프로젝트마다 고정해주는 버전 관리자이다. nvm, pyenv, fvm처럼 언어마다 따로 깔던 버전 관리자를 하나로 합쳤다. 여기서 그치지 않고 [direnv](https://mise.jdx.dev/direnv.html)와 [Make](https://www.gnu.org/software/make/)까지 겸한다.

#### [설치](https://mise.jdx.dev/installing-mise.html)

Homebrew로 설치할 수도 있지만, `mise self-update` 커맨드가 작동하려면 직접 설치하는 것이 좋다.

```zsh
curl https://mise.run | sh

# check
mise --version
```

activate 줄은 [dot_zshrc](https://github.com/rhseung/dotfiles/blob/main/dot_zshrc)에, shims 방식은 [dot_zprofile](https://github.com/rhseung/dotfiles/blob/main/dot_zprofile)에 따로 있다. 인터랙티브 셸은 `activate`가 잡고, GUI 앱이나 비인터랙티브 셸은 shims 라야 잡는다.

[셸 자동완성](https://mise.jdx.dev/cli/completion.html)도 같이 건다. `--install`이 그 셸이 찾는 자리에 완성 스크립트를 써주고, zsh의 `fpath+=`처럼 한 번 더 필요한 줄이 있으면 그건 따로 출력해준다.

```zsh
mise completion zsh --install
```

#### [Dev Tools](https://mise.jdx.dev/dev-tools/)

프로그래밍 언어 설치는 전부 Mise를 사용하여 글로벌로 설치(`mise use -g <tool>`)하면 된다.

- [Node.js](https://nodejs.org/): `node@lts`
- [Python](https://www.python.org/): `python@latest`
- [Rust](https://www.rust-lang.org/): `rust@latest`
- [Java](https://adoptium.net/): `java@latest`, Temurin 배포판으로 받아온다
- [Flutter](https://flutter.dev/): `flutter@latest`

또한, nvm, pyenv, fvm처럼 언어별로 따로 깔던 버전 관리자를 이걸로 대신한다. 프로젝트마다 `[tools]`를 다르게 둬서 디렉터리를 옮겨 다니면 버전이 자동으로 바뀌게 할 수 있다.

```toml
# project-a/mise.toml
[tools]
node = "24"
```

```zsh
cd project-a && node --version   # v24.x
cd ../project-b && node --version   # mise.toml 이 없으면 전역 버전
```

#### [Environments](https://mise.jdx.dev/environments/) - [direnv](https://direnv.net/) 대체

`mise.toml`의 `[env]`에 환경변수를 적어두면 그 디렉터리에 들어갈 때 자동으로 실린다.

```toml
[env]
DATABASE_URL = "postgres://localhost/dev"
```

기본값은 `default`로 준다.

```toml
[env]
NODE_ENV = { default = "development" }
```

`required = true`는 값을 채워주지 않고 있는지만 검사한다.

```toml
[tasks.deploy]
env = { ASC_KEY_ID = { required = true } }
run = "./deploy.sh"
```

`redact = true`를 붙이면 값을 노출하지 않고 숨겨 보안을 유지한다.

```toml
redactions = ["*_TOKEN", "*_KEY"]

[env]
DATABASE_URL = { value = "postgres://user:pass@localhost/dev", redact = true }
```

#### [Tasks](https://mise.jdx.dev/tasks/) - [Make](https://www.gnu.org/software/make/) 대체

`[tasks]`에 자주 쓰는 스크립트를 적어두고 실행할 수 있다.

```toml
[tasks.dev]
run = "bun run dev"
```

`sources`/`outputs`를 주면 입력이 안 바뀐 태스크는 건너뛴다 - 타임스탬프로 재실행 여부를 가르는 [Make](https://www.gnu.org/software/make/)의 핵심 기능 그대로다.

```toml
[tasks.build]
sources = ["src/**/*.ts"]
outputs = ["dist/**"]
run = "bun build"
```

#### [Backends](https://mise.jdx.dev/dev-tools/backends/)

언어 런타임 말고 개별 도구도 mise가 설치할 수 있다. `npm:prettier`, `pipx:black`, `cargo:ripgrep`, `go:golang.org/x/tools/gopls`, `ubi:owner/repo`처럼 백엔드를 접두어로 붙이면 그 생태계 패키지 매니저를 빌려서 설치한다. 이 글에서 `uv tool install`로 까는 [claude-swap](#claude-swap)도 원래는 여기로 통합할 수 있다.

```toml
[tools]
"npm:prettier" = "latest"
"cargo:ripgrep" = "latest"
```

#### [Hooks](https://mise.jdx.dev/hooks.html)

Enter, Leave, Preinstall, Postinstall, Watch 등의 이벤트에 커맨드를 실행한다.

단순 이벤트 뿐만 아니라 다양한 이벤트를 지원한다.

- `cd`, `enter`, `leave`, `preinstall`, `postinstall`
  ```toml
  [hooks]
  enter = "echo '프로젝트 진입'"
  leave = "echo '프로젝트 이탈'"
  postinstall = "echo '설치 완료'"
  ```
- Dev Tool 레벨의 `postinstall`
  ```toml
  [tools]
  node = { version = "20", postinstall = "npm install -g pnpm" }
  python = { version = "3.12", postinstall = "pip install pipx" }
  ```
- Task

#### [Lockfile](https://mise.jdx.dev/dev-tools/mise-lock.html)

npm의 `package-lock.json`, Rust의 `Cargo.lock`과 같은 역할을 하는 Mise의 Lockfile이다.

`lockfile = true`를 설정해두면 설치, 업그레이드할 때마다 자동으로 갱신되고, 수동으로 만들려면 `mise lock`을 돌리면 된다.

### [Bun](https://bun.com/)

JavaScript 런타임 겸 패키지 매니저이다. Node를 대신하면서 번들러와 테스트 러너까지 안고 있다.

Mise로도 깔 수 있지만 직접 깐다. `bun upgrade`가 살아 있고, 설치 스크립트가 zsh 자동완성까지 같이 붙여준다.

```zsh
curl -fsSL https://bun.com/install | bash

# check
bun --version
```

설치 스크립트가 [`~/.zshrc`](https://github.com/rhseung/dotfiles/blob/main/dot_zshrc)에 `BUN_INSTALL` PATH와 자동완성 소스 줄을 붙인다.

### [uv](https://docs.astral.sh/uv/)

Python 패키지, 프로젝트 관리자이다. pip, virtualenv, pipx, poetry가 나눠 하던 일을 하나로 합쳤고, Rust로 짜여 설치가 눈에 띄게 빠르다.

버전 관리는 Mise로 할 수 있겠지만, uv는 패키지 설치와 가상환경, 의존성 잠금(`uv.lock`) 전부 해주기 때문에 파이썬 프로젝트는 uv를 쓴다.

Mise와 같은 이유로 직접 설치한다. Homebrew로 깔면 `uv self update`가 막힌다.

```zsh
curl -LsSf https://astral.sh/uv/install.sh | sh

# check
uv --version
```

### [Ruff](https://docs.astral.sh/ruff/)

Python 린터 겸 포매터이다. flake8, isort, black이 나눠 하던 일을 하나로 합쳤고,
위의 uv와 같은 Astral이 만들어 Rust로 짜여 있다.

### [Pyrefly](https://pyrefly.org/)

Meta에서 만든 빠른 Python 타입 체커기이자 언어 서버로, Mypy를 대체한다.
덕분에, 같은 Meta에서 만든 [PyTorch에서 Pyrefly가 잘 돌아간다.](https://pytorch.kr/blog/2026/pyrefly-now-type-checks-pytorch/)

- [설치](https://pyrefly.org/en/docs/installation/)
- [VS Code용 Extension](https://marketplace.visualstudio.com/items?itemName=meta.pyrefly)

### [fnox](https://github.com/jdx/fnox)

`.env`에 평문으로 두던 비밀값을 암호화해서 저장소에 커밋하게 해주는 시크릿 매니저다. 1Password, AWS Secrets Manager 같은 원격 저장소를 지원해서 쓴다. Mise처럼 디렉토리에 들어가면 자동으로 로드된다.

```zsh
mise use -g fnox
```

```toml
# fnox.toml
[providers.onepassword]
type = "1password"

[secrets]
DATABASE_URL = { provider = "onepassword", value = "op://vault/item/field" }
```

### [claude-swap](https://github.com/realiti4/claude-swap)

Claude Code 계정을 여러 개 쓸 경우 쉽게 swap할 수 있는 CLI다. 계정마다 OAuth 토큰을 macOS Keychain에 따로 보관해두고, 전환할 때는 그 계정의 로그인 정보만 바꿔치기한다. MCP 서버 같은 공유 설정은 그대로 남는다.

[Ruff](#ruff), [Pyrefly](#pyrefly)와 달리 Homebrew에 formula가 없어서 uv로 깐다. dotfiles의 [`uv-tools.txt`](https://github.com/rhseung/dotfiles/blob/main/uv-tools.txt)에 이름을 적어두면 `chezmoi apply`가 이 명령을 대신 돌린다.

```zsh
uv tool install claude-swap

# check
cswap --version
```

계정마다 로그인한 뒤 `cswap add`로 등록해두면, `cswap list`로 계정별 5시간/7일 사용률과 리셋 시각을 확인할 수 있다.

```zsh
# 로그인한 계정을 등록
cswap add

# 계정별 사용률
cswap list

# 2번 계정으로 전환
cswap switch 2
```

`cswap auto`를 켜두면 사용률이 임계값(기본 90%)에 가까워질 때 알아서 전환한다. `best`(기본값) 전략은 여유가 가장 많은 계정으로, `consume-first`는 주간 한도가 가장 먼저 리셋되는 계정으로 옮긴다. 임계값 근처에서 왔다갔다하지 않도록 쿨다운과 히스테리시스 마진이 걸려 있다.

```zsh
cswap auto --threshold 80
```

## [Todoist](https://todoist.com/)

할 일 관리 앱이다. 자연어 처리 성능이 뛰어나고 편의 기능이 많아서 쓴다. 크로스 플랫폼, 동기화도 잘 지원한다.

### [CLI](https://www.todoist.com/ko/cli)

Doist가 만든 공식 CLI이다. 터미널에서 AI Agent가 Todoist를 사용할 수 있게 하기 위해 개발되었다.

```zsh
td auth login

# check
td auth status
td today
```

셸 자동 완성도 같이 붙인다.

```zsh
td completion install
```

### 스킬

스킬을 설치하면 [Claude Code](#claude)가 같은 목록을 읽고 쓴다. 에이전트가 만든 할 일이 도구별로 흩어지지 않는다.

```zsh
td skill install claude-code

# check
td skill list
```

## [Vercel](https://vercel.com/)

이 블로그를 배포하는 곳이다. GitHub 저장소를 물려두면 push마다 프리뷰가 서고, 기본 브랜치는 프로덕션으로 나간다.

### [CLI](https://vercel.com/docs/cli)

대시보드에서 하던 일을 터미널에서 한다. AI Agent가 쓰기도 쉽다.

```zsh
vercel login

# check
vercel whoami
```

프로젝트 폴더에서 한 번 이어둔다. `.vercel/`이 생기고 이후 명령이 그 프로젝트를 가리킨다.

```zsh
vercel link
```

대시보드에 넣어둔 환경 변수는 손으로 옮기지 않고 받아온다. 파일명을 안 주면 `.env.local`로 떨어진다.

```zsh
vercel env pull
```

배포 목록과 로그도 브라우저 없이 본다.

```zsh
vercel ls
vercel logs <deployment-url>
```
