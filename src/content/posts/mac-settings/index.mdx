## 개요

2026년 버전 개발자 Macbook 종합 세팅, 대부분의 설정은 [dotfiles](https://github.com/rhseung/dotfiles) 저장소에 들어있으나 세부적인 것을 정리하기 위해 작성했다.

해당 저장소 README에 나와있듯이 몇 가지 선행 조건을 만족한 뒤 다음 스크립트로 대부분의 설정을 적용할 수 있다.

```zsh
brew install chezmoi

chezmoi init --apply https://github.com/rhseung/dotfiles.git
brew bundle --file ~/.local/share/chezmoi/Brewfile
```

자동화 되지 않은 것들은 다음과 같다.

- **[Mise](#mise), [uv](#uv), [Bun](#bun)은 각자 설치 스크립트로 깐다.** Homebrew로 깔면 `mise self-update`, `uv self update`, `bun upgrade`가 막혀서 Brewfile에 안 넣었다.
- **직접 받는 것들**: [Raycast](#raycast-v2), 교내 배포처의 오피스류, 유료 폰트 [MonoLisa](#monolisa), [Setapp](#setapp) 안에서 받는 앱들, 한국 서버 [League of Legends](#league-of-legends).
- **GUI로만 되는 macOS 설정**

## 시스템 설정

### 컴퓨터 이름

터미널 프롬프트에서 `@` 뒤에 붙는 그 이름이다. 시스템 설정 > 일반 > 정보에서 바꿔도 프롬프트는 그대로인 경우가 많은데, macOS가 이름을 셋으로 나눠 들고 있어서다.

| 이름            | 어디에 쓰이나                                      | GUI 로 바꾸는 곳                      |
| --------------- | -------------------------------------------------- | ------------------------------------- |
| `ComputerName`  | Finder 공유 목록, 시스템 설정에 보이는 이름        | 일반 > 정보 > 이름                    |
| `LocalHostName` | Bonjour 이름. 같은 네트워크에서 `.local`로 부를 때 | 일반 > 공유 > 로컬 호스트 이름 > 편집 |
| `HostName`      | 셸 프롬프트의 `@` 뒤                               | 없음                                  |

앞의 둘은 GUI 로 된다 - 각자 다른 화면에 떨어져 있어서 `정보`만 보면 `LocalHostName`은 안 바뀐 것처럼 보일 뿐이다.

1. **시스템 설정 > 일반 > 정보 > 이름**에서 `ComputerName`을 바꾼다.
2. **시스템 설정 > 일반 > 공유**로 들어가서, 하단 `로컬 호스트 이름` 옆의 **편집**을 눌러 `LocalHostName`을 바꾼다. 공백도 한글도 못 받으니 영문 소문자와 하이픈으로 짓는다.

`HostName`은 GUI 자체가 없다. 비워두면 프롬프트에 `LocalHostName`이 `.local`을 달고 나오는데, 그게 싫으면 그때만 터미널을 쓴다.

```zsh
sudo scutil --set HostName "rhseung-macbook"
```

### 한/영 키 변경

Launch Agent와 Daemon은 macOS가 스스로 백그라운드 스크립트를 돌리는 방식이다. `~/Library/LaunchAgents`(로그인한 나만, GUI 접근 가능)와 `/Library/LaunchDaemons`(로그인 전부터, 시스템 전체) 둘로 나뉜다.

오른쪽 <Shortcut keys={['cmd']} /> (HID 0x7000000E7)를 <Shortcut keys={['F18']} /> (0x70000006D)로 보낸다.

아래 LaunchAgent부터 등록해서 매핑을 먼저 켜야 한다. 노트북 키보드엔 <Shortcut keys={['F18']} />이 물리 키로 없어서, 오른쪽 <Shortcut keys={['cmd']} />가 그 신호를 실제로 보내고 있어야만 다음 단계에서 단축키 녹화기가 F18을 잡을 수 있다.

```xml
<!-- ~/Library/LaunchAgents/local.hidutil.rcmd-to-f18.plist -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>local.hidutil.rcmd-to-f18</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/bin/hidutil</string>
    <string>property</string>
    <string>--set</string>
    <string>{"UserKeyMapping":[{"HIDKeyboardModifierMappingSrc":0x7000000E7,"HIDKeyboardModifierMappingDst":0x70000006D}]}</string>
  </array>
  <key>RunAtLoad</key>
  <true/>
</dict>
</plist>
```

`hidutil`로 키를 바로 리매핑할 수는 있지만 재부팅하면 풀린다. LaunchAgent에 `RunAtLoad`로 걸어두면 로그인할 때마다 다시 걸린다.

이후 아래 스크립트를 실행한다.

```zsh
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/local.hidutil.rcmd-to-f18.plist

# check
hidutil property --get UserKeyMapping
```

매핑이 걸렸으면 **시스템 설정 > 키보드 > 키보드 단축키 > 입력 소스**로 들어가서 "이전 입력 소스 선택" 체크박스를 켜고 단축키를 Right <Shortcut keys={['cmd']} />로 바꾸면 된다.

## 개발 환경 준비

### macOS 업데이트와 칩 확인

먼저 macOS를 최신 상태로 업데이트한다.

```zsh
softwareupdate --list
```

또한 현재 macOS 버전은 다음과 같이 확인할 수 있다.

```zsh
sw_vers
```

Mac의 칩 종류는 아래 명령어로 확인한다.

```zsh
uname -m
```

결과가 `arm64` 라면 Apple Silicon 계열이며, `x86_64` 이면 Intel Mac이다.

### 개발 폴더

저장소는 홈 아래 `~/Developer`에 clone해서 쓴다. macOS가 몇몇 홈 폴더 이름을 예약어로 다뤄서 전용 아이콘을 자동으로 붙여주는데, `Developer`도 그중 하나다.

```zsh
mkdir -p ~/Developer
```

### [Xcode Command Line Tools](https://developer.apple.com/documentation/xcode/installing-the-command-line-tools)

clang 컴파일러와 SDK 헤더, 그리고 Homebrew 설치에 필요하여 먼저 Xcode Command Line Tools를 설치하는 것이 좋다.

```zsh
xcode-select --install

# check
xcode-select -p
clang --version
```

### [Homebrew](https://brew.sh/)

가장 유명한 macOS 패키지 매니저이다.

```zsh
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

이후 터미널에 Next steps 항목이 나오는데, 그걸 따라 `~/.zshrc` 같은 각 터미널 설정 파일에 넣어주면 된다.

### [mas](https://github.com/mas-cli/mas)

Mac App Store CLI. App Store 앱을 GUI 대신 CLI로 사용할 수 있어, [Homebrew](#homebrew)에 없는 앱들은 `mas`로 설치해주면 된다.

```zsh
brew install mas

# check
mas version
```

```zsh
mas search klack
mas install 6446206067
```

## 필수 앱

1Password를 먼저 설치한다. 뒤에 나오는 대부분이 로그인을 요구하기 때문이다.

### [1Password](https://1password.com/)

비밀번호와 패스키, 2단계 인증 코드를 한 금고에 모아 기기 사이로 동기화해주는 관리 앱이다. SSH 키와 API 토큰까지 같은 금고에 넣어 Touch ID로 꺼내 쓸 수 있다.

```zsh
brew install --cask 1password 1password-cli
```

[1Password CLI](https://developer.1password.com/docs/cli/)까지 같이 깔면 [셸 플러그인](https://developer.1password.com/docs/cli/shell-plugins/)이 붙는다. `gh`나 `aws`처럼 토큰이 필요한 CLI를 Touch ID로 대신 인증해주고, [git 커밋 서명](https://developer.1password.com/docs/ssh/git-commit-signing/)은 SSH 에이전트가 금고의 키로 처리한다.

#### 커밋 서명

금고에서 **New Item > SSH Key** 로 키를 만든다. `ssh-keygen` 으로 만들어 넣어도 되지만, 금고에서 만들면 개인 키가 금고 밖으로 유출될 일이 없기에 이 방법을 추천한다.

앱 설정의 **Developer** 탭에 SSH 에이전트를 켜고 git 커밋 서명까지 대신 해주는 버튼이 있다. 눌러 두면 `~/.ssh/config`와 `~/.gitconfig`를 알아서 써 주니 할 일은 GitHub에 공개키를 **Signing Key** 타입으로 올리면 된다.

### [AdGuard](https://adguard.com/ko/welcome.html)

로컬 프록시로 트래픽을 거쳐 보내며 브라우저 밖 앱 안의 광고까지 걸러주는 차단기이다.

```zsh
brew install --cask adguard
```

AdGuard는 다양한 옵션을 지원하는데, 한국의 웹사이트들에서도 잘 작동하게 하려면 커스텀 필터, 유저스크립트를 추가해야한다.

- [filterslists-KO](https://github.com/FilteringDev/filterslists-KO): AdGuard와 애드블록 커뮤니티에서 관리하는 한국어 광고 차단 필터 리스트
- [tinyShield](https://github.com/FilteringDev/tinyShield): Ad-Shield 방식의 Adblock Blocker를 막는 유저스크립트
- [NamuLink](https://github.com/FilteringDev/NamuLink): 나무위키의 처리하기 복잡한 파워링크를 차단하는 유저스크립트
- [crackle](https://github.com/FilteringDev/crackle): 네이버 치지직 웹 사이트의 광고 제거 및 안티 애드블록 우회를 위한 유저스크립트

### [Google Chrome](https://www.google.com/intl/ko_kr/chrome/)

점유율이 가장 높은 브라우저이다. 여러 플랫폼에서 지원하며 구글 계정 연동이 강력하여 사용한다. 또한, 프론트엔드 개발자는 대다수가 쓰는 환경에서 테스트를 해야 하기에 쓸 수 밖에 없다...

```zsh
brew install --cask google-chrome
```

## 유틸리티 앱

### [Alcove](https://tryalcove.com/)

아이폰의 다이나믹 아일랜드를 맥 노치로 옮겨온 앱이다. 재생 중인 음악, 에어드랍, 충전, 캘린더 등의 여러 기능을 가지고 있어 편리하다.

```zsh
brew install --cask alcove
```

### [Klack](https://tryklack.com/)

키를 누를 때 기계식 키보드 소리를 내준다. [App Store](https://apps.apple.com/us/app/klack/id6446206067?mt=12)에서 설치한다.

```zsh
mas install 6446206067
```

### [Vorssaint](https://vorssaint.com/)

macOS 메뉴 바에서 쓰는 무료 오픈소스 시스템 툴킷이다. 화면을 닫아도 절전에 안 들어가게 하는 Keep-awake, CPU/GPU 온도와 배터리, 메모리 모니터링, 네트워크, 디스크 속도 표시, 다크 모드, 마이크 음소거 같은 빠른 토글까지 모듈식으로 필요한 것만 골라 켤 수 있다.

```zsh
brew install --cask vorssaint
```

### [Gitify](https://www.gitify.io/)

메뉴 바에서 GitHub, GitLab, Gitea, Bitbucket 알림을 받는 무료 오픈소스 앱이다. 여러 플랫폼의 여러 계정을 한 번에 묶어서 보고, 필요한 알림만 걸러낼 수 있다.

```zsh
brew install --cask gitify
```

#### Nerd Font 글리프

MonoLisa는 Nerd Font 글리프를 담고 있지 않다. [MonoLisa FAQ](https://www.monolisa.dev/faq#how-to-enable-nerd-fonts-with-monolisa)는 폰트를 직접 패치하기보다 폴백 폰트를 두는 쪽을 권한다. 패치본은 MonoLisa를 새로 받을 때마다 다시 구워야 한다.

아이콘 글리프만 담은 Symbols Nerd Font가 그 폴백이다.


[VS Code](#visual-studio-code)는 `fontFamily`에 콤마로 잇는다.

```json
"terminal.integrated.fontFamily": "'MonoLisaCode', 'Symbols Nerd Font Mono', 'Pretendard GOV Variable', Menlo, Monaco, 'Courier New', monospace"
```

[Ghostty](#ghostty)는 `font-family`를 줄마다 하나씩 쌓아 폴백을 만든다.

```
font-family = "MonoLisaCode"

font-family = "Pretendard GOV Variable"
```

```zsh

cd nerd-fonts

./font-patcher ~/Library/Fonts/MonoLisa-Regular.ttf --complete
```

패치된 폰트가 `~/Library/Fonts`에 새로 생기면 그걸 터미널·에디터 설정의 `font-family`에 지정한다.

### Zsh

#### 플러그인

`fzf-tab`은 zsh의 기본 선택 메뉴를 [fzf](#fzf)로 갈아끼우는 것이라 fzf가 깔려 있어야 한다. 로드 순서가 까다롭다.

- `zsh-completions`는 `FPATH`에 얹히므로 `compinit` 앞
- `fzf-tab`은 `compinit` 뒤이면서, 위젯을 감싸는 `zsh-autosuggestions`·`zsh-syntax-highlighting`보다 앞
- `zsh-syntax-highlighting`은 `zsh-history-substring-search`보다 먼저

```zsh
brew install zsh-completions zsh-autosuggestions zsh-syntax-highlighting zsh-history-substring-search zsh-you-should-use fzf-tab
```

`~/.zshrc`에 이 순서로 넣는다. 경로의 `$HOMEBREW_PREFIX`는 [Homebrew](#homebrew) 설정 때 넣은 `brew shellenv`가 채워주므로 Intel/ARM을 안 가린다.

```zsh
# zsh-completions 는 FPATH 방식이라 compinit 보다 앞
FPATH="$HOMEBREW_PREFIX/share/zsh-completions:$FPATH"
autoload -Uz compinit && compinit

# fzf-tab 은 compinit 뒤, 위젯을 래핑하는 autosuggestions/syntax-highlighting 보다 앞
source "$HOMEBREW_PREFIX/opt/fzf-tab/share/fzf-tab/fzf-tab.zsh"

source "$HOMEBREW_PREFIX/share/zsh-autosuggestions/zsh-autosuggestions.zsh"

# syntax-highlighting 은 history-substring-search 보다 먼저
source "$HOMEBREW_PREFIX/share/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh"

source "$HOMEBREW_PREFIX/share/zsh-history-substring-search/zsh-history-substring-search.zsh"
bindkey '^[[A' history-substring-search-up # 위 화살표
bindkey '^[[B' history-substring-search-down # 아래 화살표

source "$HOMEBREW_PREFIX/share/zsh-you-should-use/you-should-use.plugin.zsh"
```

- [zsh-completions](https://github.com/zsh-users/zsh-completions): 기본 zsh에 없는 커맨드용 자동완성 정의 모음
- [zsh-autosuggestions](https://github.com/zsh-users/zsh-autosuggestions): 히스토리 기반으로 입력 중인 줄 뒤에 회색 제안을 띄운다.
- [zsh-syntax-highlighting](https://github.com/zsh-users/zsh-syntax-highlighting): 입력하는 즉시 명령어, 경로에 문법 강조를 입힌다.
- [zsh-history-substring-search](https://github.com/zsh-users/zsh-history-substring-search): 위/아래 화살표로 지금까지 입력한 부분 문자열을 포함하는 히스토리만 훑는다.
- [zsh-you-should-use](https://github.com/MichaelAquilina/zsh-you-should-use): 방금 친 명령이 등록된 alias 로 대체 가능하면 알려준다

#### Git 설정

`git config --global`을 한 번에 모았다. 이름과 이메일은 [커밋 서명](#커밋-서명)까지 했다면 서명 키의 이메일과 맞춰야 한다.

```zsh
git config --global user.name "Hyunseung Ryu"
git config --global user.email "ryu@rhseung.me"
git config --global init.defaultBranch main
```

diff는 [delta](#delta)로 페이저를 설정하면 된다.

```zsh
git config --global core.pager delta
git config --global interactive.diffFilter "delta --color-only"
git config --global delta.navigate true
git config --global delta.dark true
```

머지 충돌은 `zdiff3`로 바꾼다. `zdiff3`은 conflict 전 원본 내용까지 같이 보여줘서 가늠하기가 더 쉽다. git에 내장된 옵션이라 따로 설치할 건 없다.

```zsh
git config --global merge.conflictStyle zdiff3
```

macOS가 폴더마다 생성하는 `.DS_Store`는 글로벌 `.gitignore`에 적는 것이 낫다. `~/.config/git/ignore`가 기본 전역 gitignore이므로, 그 파일을 수정한다:

```zsh
echo ".DS_Store" >> ~/.config/git/ignore
```

## 언어 환경

### [Mise](https://mise.jdx.dev/)

Node, Python, Rust 같은 런타임 버전을 프로젝트마다 고정해주는 버전 관리자이다. nvm, pyenv, fvm처럼 언어마다 따로 깔던 버전 관리자를 하나로 합쳤다. 여기서 그치지 않고 [direnv](https://mise.jdx.dev/direnv.html)와 [Make](https://www.gnu.org/software/make/)까지 겸한다.

#### [설치](https://mise.jdx.dev/installing-mise.html)

Homebrew로 설치할 수도 있지만, `mise self-update` 커맨드가 작동하려면 직접 설치하는 것이 좋다.

```zsh
curl https://mise.run | sh

echo 'eval "$(~/.local/bin/mise activate zsh)"' >> ~/.zshrc
echo 'eval "$(~/.local/bin/mise activate zsh --shims)"' >> ~/.zprofile

# check
mise --version
```

[셸 자동완성](https://mise.jdx.dev/cli/completion.html)도 같이 건다. `--install`이 그 셸이 찾는 자리에 완성 스크립트를 써주고, zsh의 `fpath+=`처럼 한 번 더 필요한 줄이 있으면 그건 따로 출력해준다.

```zsh
mise completion zsh --install
```

#### [Dev Tools](https://mise.jdx.dev/dev-tools/)

프로그래밍 언어 설치는 전부 Mise를 사용하여 글로벌로 설치(`mise use -g <tool>`)하면 된다.

- [Node.js](https://nodejs.org/): `node@lts`
- [Python](https://www.python.org/): `python@latest`
- [Rust](https://www.rust-lang.org/): `rust@latest`
- [Java](https://adoptium.net/): `java@latest`, Temurin 배포판으로 받아온다
- [Flutter](https://flutter.dev/): `flutter@latest`

또한, nvm, pyenv, fvm처럼 언어별로 따로 깔던 버전 관리자를 이걸로 대신한다. 프로젝트마다 `[tools]`를 다르게 둬서 디렉터리를 옮겨 다니면 버전이 자동으로 바뀌게 할 수 있다.

```toml
# project-a/mise.toml
[tools]
node = "24"
```

```zsh
cd project-a && node --version   # v24.x
cd ../project-b && node --version   # mise.toml 이 없으면 전역 버전
```

#### [Environments](https://mise.jdx.dev/environments/) - [direnv](https://direnv.net/) 대체

`mise.toml`의 `[env]`에 환경변수를 적어두면 그 디렉터리에 들어갈 때 자동으로 실린다.

```toml
[env]
DATABASE_URL = "postgres://localhost/dev"
```

기본값은 `default`로 준다.

```toml
[env]
NODE_ENV = { default = "development" }
```

`required = true`는 값을 채워주지 않고 있는지만 검사한다.

```toml
[tasks.deploy]
env = { ASC_KEY_ID = { required = true } }
run = "./deploy.sh"
```

`redact = true`를 붙이면 값을 노출하지 않고 숨겨 보안을 유지한다.

```toml
redactions = ["*_TOKEN", "*_KEY"]

[env]
DATABASE_URL = { value = "postgres://user:pass@localhost/dev", redact = true }
```

#### [Tasks](https://mise.jdx.dev/tasks/) - [Make](https://www.gnu.org/software/make/) 대체

`[tasks]`에 자주 쓰는 스크립트를 적어두고 실행할 수 있다.

```toml
[tasks.dev]
run = "bun run dev"
```

`sources`/`outputs`를 주면 입력이 안 바뀐 태스크는 건너뛴다 - 타임스탬프로 재실행 여부를 가르는 [Make](https://www.gnu.org/software/make/)의 핵심 기능 그대로다.

```toml
[tasks.build]
sources = ["src/**/*.ts"]
outputs = ["dist/**"]
run = "bun build"
```

#### [Backends](https://mise.jdx.dev/dev-tools/backends/)

언어 런타임 말고 개별 도구도 mise가 설치할 수 있다. `npm:prettier`, `pipx:black`, `cargo:ripgrep`, `go:golang.org/x/tools/gopls`, `ubi:owner/repo`처럼 백엔드를 접두어로 붙이면 그 생태계 패키지 매니저를 빌려서 설치한다. 지금 이 글에서 `uv tool install`, `cargo install`로 따로 까는 것들도 원래는 여기로 통합할 수 있다.

```toml
[tools]
"npm:prettier" = "latest"
"cargo:ripgrep" = "latest"
```

#### [Hooks](https://mise.jdx.dev/hooks.html)

Enter, Leave, Preinstall, Postinstall, Watch 등의 이벤트에 커맨드를 실행한다.

단순 이벤트 뿐만 아니라 다양한 이벤트를 지원한다.

- `cd`, `enter`, `leave`, `preinstall`, `postinstall`
  ```toml
  [hooks]
  enter = "echo '프로젝트 진입'"
  leave = "echo '프로젝트 이탈'"
  postinstall = "echo '설치 완료'"
  ```
- Dev Tool 레벨의 `postinstall`
  ```toml
  [tools]
  node = { version = "20", postinstall = "npm install -g pnpm" }
  python = { version = "3.12", postinstall = "pip install pipx" }
  ```
- Task

#### [Lockfile](https://mise.jdx.dev/dev-tools/mise-lock.html)

npm의 `package-lock.json`, Rust의 `Cargo.lock`과 같은 역할을 하는 Mise의 Lockfile이다.

`lockfile = true`를 설정해두면 설치, 업그레이드할 때마다 자동으로 갱신되고, 수동으로 만들려면 `mise lock`을 돌리면 된다.

### [claude-swap](https://github.com/realiti4/claude-swap)

Claude Code 계정을 여러 개 쓸 경우 쉽게 swap할 수 있는 CLI다. 계정마다 OAuth 토큰을 macOS Keychain에 따로 보관해두고, 전환할 때는 그 계정의 로그인 정보만 바꿔치기한다. MCP 서버 같은 공유 설정은 그대로 남는다.

위의 [Ruff](#ruff), [Pyrefly](#pyrefly)와 같이 uv로 깐다.

```zsh
uv tool install claude-swap

# check
cswap --version
```

계정마다 로그인한 뒤 `cswap add`로 등록해두면, `cswap list`로 계정별 5시간/7일 사용률과 리셋 시각을 확인할 수 있다.

```zsh
# 로그인한 계정을 등록
cswap add

# 계정별 사용률
cswap list

# 2번 계정으로 전환
cswap switch 2
```

`cswap auto`를 켜두면 사용률이 임계값(기본 90%)에 가까워질 때 알아서 전환한다. `best`(기본값) 전략은 여유가 가장 많은 계정으로, `consume-first`는 주간 한도가 가장 먼저 리셋되는 계정으로 옮긴다. 임계값 근처에서 왔다갔다하지 않도록 쿨다운과 히스테리시스 마진이 걸려 있다.

```zsh
cswap auto --threshold 80
```

```md
## Commits

**커밋 하나에 변경 하나.** 스테이지한 변경이 서로 독립적으로 되돌려질 수 있으면 커밋을 나눈다.
**이미 만든 커밋은 건드리지 않는다.** 리뷰 지적이든 추가 수정이든 새 커밋으로 쌓는다.
**제목은 영어, 본문은 한국어.**
`<type>: <title>`, 명령형으로 쓴다.

## Comments

**주석은 코드가 말할 수 없는 것만 적는다.** 무엇을 하는지는 코드가 이미 말한다 -
적을 값어치가 있는 건 _왜 이 방식이어야 하는지_, 특히 다르게 짜면 깨지는 이유다.
TODO, FIXME 같은 태그형 주석 말고는 설명형 주석을 최소화한다 - 주석이 필요 없을 만큼
가독성 좋고 간결하게 짜는 게 우선이다. 주석은 많을수록 좋은 게 아니다.
```
